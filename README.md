# Visual Regression Testing System

## How It Works

```
Designer creates/updates design in pencil.dev
              ↓
Developer generates React components (Vite+ app with Storybook)
              ↓
VRT system exports pencil.dev design frames as baseline images
              ↓
Playwright screenshots each Storybook story
              ↓
Compares screenshot vs pencil.dev baseline pixel-by-pixel
              ↓
Discrepancy found? → Claude Code reads pencil.dev via MCP → fixes the code
```

## Prerequisites

### 1. Node.js

Version 18 or higher is required.

```bash
node --version  # should be v18+
```

### 2. Claude Code

Claude Code must be installed, authenticated, and running in the same terminal session where you run VRT commands.

**Install Claude Code:**

```bash
npm install -g @anthropic-ai/claude-code
```

**Authenticate Claude Code:**

Run the setup token command to generate a long-lived authentication token fi=or terminal without explicit claude session:

```bash
claude setup-token
```

This will output something like:

```
✓ Long-lived authentication token created successfully!

Your OAuth token (valid for 1 year):

<<your-token-here>>

Store this token securely. You won't be able to see it again.
Use this token by setting: export CLAUDE_CODE_OAUTH_TOKEN=<token>
```

**Set the token in your environment:**

On **macOS / Linux**:

```bash
export CLAUDE_CODE_OAUTH_TOKEN=your_token_here
```

To make it permanent, add it to your `~/.bashrc`, `~/.zshrc`, or `~/.bash_profile`:

```bash
echo 'export CLAUDE_CODE_OAUTH_TOKEN=your_token_here' >> ~/.zshrc
source ~/.zshrc
```

On **Windows (PowerShell)**:

```powershell
$env:CLAUDE_CODE_OAUTH_TOKEN="your_token_here"
```

To make it permanent in PowerShell, add it to your profile:

```powershell
Add-Content $PROFILE "`n`$env:CLAUDE_CODE_OAUTH_TOKEN='your_token_here'"
```

To make it permanent via Windows System Settings:

1. Open **System Properties** → **Advanced** → **Environment Variables**
2. Under **User Variables**, click **New**
3. Variable name: `CLAUDE_CODE_OAUTH_TOKEN`
4. Variable value: your token

**Verify Claude Code is working:**

```bash
claude --version
claude --print "hello"
```

### 3. Playwright Browsers

Install Chromium for Playwright:

```bash
npm run install:browsers
```

### 4. pencil.dev

- Download and install [pencil.dev](https://pencil.dev)
- open seeting > agents and make sure anthropi claude code is connected
- pencil.dev must be **open with your `.pen` design file loaded** whenever you run `vrt:sync` or `vrt:run`
- pencil.dev connects to Claude Code via MCP automatically — you can verify this by running:

```bash
claude --print "list your active MCP servers"
```

You should see `pencil` listed as an active MCP server.

### 5. Your Frontend App (Repo 1)

The React app generated by pencil.dev must have:

- Storybook set up and running at `http://localhost:6006` (or your configured URL)
- A Storybook story for **every component** — the VRT system only tests components that have stories

> **Convention:** Every component generated by pencil.dev must have a corresponding Storybook story before it can be tested. No story = no test.

## Configuration

### Create a `.env` file

Create a `.env` file in the root of this repo:

```dotenv
# Path to your Vite+ React app (Repo 1) — absolute  path example("C:\Users\User\Documents\GitHub\test")
# This is where pencil.dev generated your component
REPO1_PATH=../your-app

# Claude Code session token — required for non-interactive MCP access
# Generate this by running: claude setup-token
# Then set it here AND as an environment variable (see Prerequisites)
CLAUDE_CODE_SESSION_ACCESS_TOKEN=your_session_token_here

# URL where Storybook is running (default: http://localhost:6006)
# Only change this if your Storybook runs on a different port or host
# make sure storybook on repo 1 is running
STORYBOOK_URL=http://localhost:6006
```

**What each variable means:**

| Variable                           | Required | Description                                                                                                                          |
| ---------------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `REPO1_PATH`                       | Yes      | Path to your React app where pencil.dev generated the components. The AI fix agent reads and patches source files here.              |
| `CLAUDE_CODE_SESSION_ACCESS_TOKEN` | Yes      | Authentication token for Claude Code to run in non-interactive mode. Required for `vrt:sync` and `vrt:fix` to call pencil MCP tools. |
| `STORYBOOK_URL`                    | No       | Where Storybook is running. Defaults to `http://localhost:6006`. Change if you run Storybook on a different port.                    |

## Naming Convention — Critical

The VRT system automatically matches pencil.dev design frames to Storybook stories by name. For this to work, **component names in pencil.dev must closely match the Storybook story titles**.

| pencil.dev frame name | Storybook story title          | Matches? |
| --------------------- | ------------------------------ | -------- |
| `Button/Primary`      | `Components/Button > Primary`  | ✓ Yes    |
| `Dashboard/Frame 74`  | `Components/Frame74 > Default` | ✓ Yes    |
| `MyCard`              | `Components/Card > Default`    | ✓ Yes    |
| `xyz123`              | `Components/Button > Primary`  | ✗ No     |

If names don't match, the sync will report unmatched nodes and those components won't get pencil.dev baselines.

## Workflow

### One-time setup (when starting a new project)

```bash
# 1. Make sure Storybook is running in Repo 1
# 2. Make sure pencil.dev is open with your .pen file

# Generate test files from Storybook
npm run vrt:generate

# Pull pencil.dev design frames as baselines
npm run vrt:sync
```

### Day-to-day usage

After pencil.dev generates new or updated components:

```bash
npm run vrt:run
```

This runs the full pipeline automatically:

1. Discovers stories from Storybook
2. Runs Playwright visual tests
3. If failures found → Claude Code reads pencil.dev design via MCP and fixes the code
4. Re-runs tests to verify fixes

### When the designer updates the design in pencil.dev

```bash
# Re-pull the updated design frames as new baselines
npm run vrt:sync

# Then run tests against the updated baselines
npm run vrt:run
```

| Command                         | Description                                       |
| ------------------------------- | ------------------------------------------------- |
| `npm run vrt:run`               | Full pipeline — generate, test, fix, verify       |
| `npm run vrt:run:update`        | Reset baselines from current Storybook state      |
| `npm run vrt:run:skip-fix`      | Run tests only, skip AI fix agent                 |
| `npm run vrt:run:skip-generate` | Skip story discovery, use existing test file      |
| `npm run vrt:generate`          | Discover Storybook stories and generate test file |
| `npm run vrt:sync`              | Export pencil.dev design frames as baselines      |
| `npm run vrt:fix`               | Run AI fix agent on last set of failures          |
| `npm run vrt:report`            | Open the last Playwright HTML report              |
| `npm run install:browsers`      | Install Playwright's Chromium browser             |

## Important Rules

**Always have pencil.dev open** when running `vrt:sync` or `vrt:run`. The AI fix agent connects to pencil.dev via MCP to read the design spec when fixing components.

**Always have Storybook running** before running any VRT command. All scripts fetch story data from `localhost:6006` (or your configured `STORYBOOK_URL`).

**Back up files before applying fixes.** The AI fix agent automatically creates `.bak` backup files (e.g. `Button.css.bak`) before patching. Review diffs before committing.

## Troubleshooting

**`Claude Code exited with code null`**
Claude Code timed out or was denied tool permissions. Run the fix interactively to see what's happening:

**`No nodes were matched`**
Pencil.dev frame names don't match Storybook story names closely enough. Rename frames in pencil.dev to match your component names (see Naming Convention above).

**Tests pass but component looks wrong**
The baseline image may be stale. Re-sync from pencil.dev:

```bash
npm run vrt:sync
```

## How the AI Fix Agent Works

When a test fails the AI fix agent:

1. Reads `reports/results.json` to find failing tests
2. Finds the component's source files (`.tsx` and `.css`) in `REPO1_PATH`
3. Collects three images: the **expected** (pencil.dev baseline), the **actual** (current screenshot), and the **diff** (highlighted differences)
4. Calls Claude Code with all of the above plus a prompt asking it to fix the code
5. Claude Code calls the pencil MCP to read the exact design spec (colours, spacing, font sizes, border radius)
6. Claude Code generates a minimal patch — only changing what's needed
7. The patch is applied directly to the source files in `REPO1_PATH`
8. A backup `.bak` file is created for every patched file
9. Playwright re-runs to verify the fix worked

All fixes are logged to `reports/ai-fixes.json` with the diagnosis, confidence level, and exact patches applied.
